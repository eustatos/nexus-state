# Риски и митигация

## Риски Фазы 1: @nexus-state/undo-redo

### Риск 1: Производительность для больших состояний
**Вероятность**: Средняя  
**Влияние**: Высокое

**Описание**: JSON.stringify/parse может быть медленным для больших объектов.

**Митигация**:
- Использовать structural cloning где возможно
- Добавить опцию для custom serialization
- Документировать ограничения по размеру состояния
- Добавить benchmarks

### Риск 2: Memory leaks при большой истории
**Вероятность**: Средняя  
**Влияние**: Высокое

**Описание**: Хранение 50+ состояний может занимать много памяти.

**Митигация**:
- Строгое соблюдение maxLength
- Добавить метод для очистки истории
- Документировать best practices
- Добавить опцию для shallow copy

### Риск 3: Конфликты с keyboard shortcuts
**Вероятность**: Низкая  
**Влияние**: Среднее

**Описание**: Ctrl+Z может конфликтовать с браузерными shortcuts.

**Митигация**:
- Сделать shortcuts опциональными
- Добавить возможность кастомизации
- Документировать потенциальные конфликты

## Риски Фазы 2: @nexus-state/time-travel

### Риск 1: Циклические зависимости
**Вероятность**: Средняя  
**Влияние**: Критическое

**Описание**: time-travel может создать циклическую зависимость с core.

**Митигация**:
- Тщательно спроектировать API границы
- Использовать peer dependencies
- Проверять зависимости на каждом этапе
- Использовать dependency-cruiser

### Риск 2: Breaking changes в API
**Вероятность**: Высокая  
**Влияние**: Высокое

**Описание**: Изменение импортов сломает существующий код.

**Митигация**:
- Создать re-exports в core
- Добавить deprecation warnings
- Написать подробный migration guide
- Поддерживать backward compatibility минимум 2 major версии

---

## Риски Фазы 3: Рефакторинг core

### Риск 1: Сломать существующие пакеты
**Вероятность**: Высокая  
**Влияние**: Критическое

**Описание**: Удаление time-travel может сломать 19 зависимых пакетов.

**Митигация**:
- Создать re-exports для backward compatibility
- Тестировать каждый зависимый пакет
- Использовать semver правильно (major version bump)
- Создать comprehensive test suite

### Риск 2: Размер не уменьшится как ожидается
**Вероятность**: Низкая  
**Влияние**: Среднее

**Описание**: Могут остаться скрытые зависимости.

**Митигация**:
- Использовать bundle analyzer
- Проверять размер на каждом этапе
- Удалять неиспользуемый код агрессивно

## Риски Фазы 5: Миграция

### Риск 1: Пропустить пакет при миграции
**Вероятность**: Средняя  
**Влияние**: Высокое

**Описание**: Можем забыть обновить какой-то пакет.

**Митигация**:
- Использовать автоматизированный поиск зависимостей
- Создать checklist всех пакетов
- Запускать monorepo-wide тесты

### Риск 2: Тесты не покрывают все сценарии
**Вероятность**: Высокая  
**Влияние**: Среднее

**Описание**: Могут быть edge cases без тестов.

**Митигация**:
- Добавить integration tests
- Тестировать в реальных проектах
- Создать beta версию для early adopters

### Риск 1: Неполная документация

**Влияние**: Среднее

- Проверять package.json перед публикацией
- Иметь rollback план

## Общие риски

### Риск 1: Недооценка времени
**Вероятность**: Высокая  
**Влияние**: Среднее

**Описание**: Рефакторинг может занять больше 6-7 дней.

**Митигация**:
- Добавить 30% buffer к оценкам
- Приоритизировать критические задачи
- Готовность к итеративному подходу

### Риск 2: Потеря backward compatibility
**Вероятность**: Средняя  
**Влияние**: Критическое

**Описание**: Пользователи не смогут обновиться без breaking changes.

**Митигация**:
- Строгое следование semver
- Поддержка старых API через re-exports
- Длительный deprecation период (2+ major versions)
