# Шаблон задачи на написание тестов

# TASK-XX: Написание тестов для <ИмяФайла>.ts

## Описание
Написание полного набора тестов для `<путь/к/файлу>.ts`

## Метаданные
- **Приоритет:** <P1|P2|P3>
- **Сложность:** <Низкая|Средняя|Высокая>
- **Оценка:** <X> часов
- **Файл:** `packages/core/src/<путь>/<файл>.ts` (<N> строк)
- **Текущее покрытие:** <X>%

## Требования
- [ ] **strict: true** — никаких `any`, все типы явные
- [ ] **SPR** — разбить на <N> PR ≤ 200 строк каждый
- [ ] **TDD** — тесты пишутся перед проверкой
- [ ] **Покрытие:** ≥ 90% строк, ≥ 85% функций

## Задачи

### 1. Анализ кода (1 час)
- [ ] Изучить публичный API класса/модуля
- [ ] Выявить все публичные методы/функции
- [ ] Определить зависимости
- [ ] Задокументировать ожидаемое поведение

### 2. Создание тестового файла (1 час)
- [ ] Создать `__tests__>/<ИмяФайла>.test.ts`
- [ ] Настроить моки для зависимостей
- [ ] Создать фикстуры для тестов

### 3. Написание тестов (<X> часов)
- [ ] Тесты на конструктор/инициализацию
- [ ] Тесты на основные методы/функции
- [ ] Тесты на обработку ошибок
- [ ] Тесты на граничные случаи
- [ ] Интеграционные тесты (при необходимости)

### 4. Проверка качества (1 час)
- [ ] `pnpm build` — успешно
- [ ] `pnpm lint` — без ошибок
- [ ] `pnpm tsc --noEmit` — без ошибок
- [ ] `pnpm test` — все тесты проходят
- [ ] Проверить покрытие ≥ 90%

## Критерии приёмки
1. Все публичные методы покрыты тестами
2. Обработка ошибок протестирована
3. Граничные случаи учтены
4. Нет TODO в коде
5. Сборка и линтинг проходят
