# ART-000: Исследование проблем отладки состояний (Research)

## 📋 Описание

Проведение исследования проблем и задач, связанных с отладкой состояния store в современных приложениях, с фокусом на редакторы (текстовые, графические, видео, звуковые).

## 🎯 Цель

Собрать эмпирические данные и качественные инсайты о:
1. Типичных проблемах отладки состояний
2. Специфике редакторов как домена
3. Существующих решениях и их недостатках
4. Ожиданиях пользователей от undo/redo

**Результат:** Раздел «Проблема» в статье с реальными данными, а не предположениями.

### Направление 4: Технические решения

**Вопросы для исследования:**
1. Какие паттерны используются для undo/redo?
2. Как хранится история (snapshot vs command vs delta)?
3. Как оптимизируется память?
4. Как реализуется serialisation для экспорта?

**Методы сбора:**
- [ ] Анализ открытых реализаций
- [ ] Изучение академических статей
- [ ] Анализ паттернов из книг (GoF, Architecture Patterns)

**Объекты исследования:**

| Паттерн | Описание | Плюсы | Минусы | Где используется |
|---------|----------|-------|--------|------------------|
| **Snapshot** | Полное копирование состояния | Простота | Память | Photoshop, Figma |
| **Command** | Команды с execute/undo | Гибкость | Сложность | VS Code |
| **Delta** | Только изменения | Эффективность | Сложность сравнения | Google Docs |
| **Memento** | Снимки + метаданные | Баланс | overhead | Nexus State |

**Шаблон анализа реализации:**
```typescript
// Пример: Command Pattern
interface Command {
  execute(): void
  undo(): void
  redo(): void
}

// Пример: Snapshot
type Snapshot = {
  timestamp: number
  state: AppState
  metadata: { action: string }
}

// Пример: Delta
type Delta = {
  type: 'insert' | 'delete' | 'replace'
  position: number
  content: string
}
```

**Ожидаемый результат:**
- Сравнительная таблица паттернов
- Рекомендации по выбору для разных типов редакторов
- Обоснование выбора Nexus State (delta + snapshot hybrid)
