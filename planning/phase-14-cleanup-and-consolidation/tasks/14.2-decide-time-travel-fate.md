# Task 14.2: Decide Time-Travel Fate

| Meta | Value |
|------|-------|
| **Task** | Make explicit decision on time-travel API: accept, reject, or defer |
| **Priority** | P1 — resolves planning limbo |
| **Estimated effort** | Small |
| **Breaking changes** | No — documentation only |
| **Dependencies** | Task 14.1 (DevTools decision affects time-travel) |

## Context

**Planned (Phase 12.4):**

```typescript
// Core API
store.snapshot(): Snapshot;
store.restore(snapshot: Snapshot): void;

// TimeTravelManager
class TimeTravelManager {
  back(): void;
  forward(): void;
  currentIndex: number;
  historyLength: number;
  clear(): void;
}
```

**Actual (2026-07-10):**

- No `snapshot()` / `restore()` methods on Store
- No `TimeTravelManager` class in core
- Only `setByName(name, value)` exists (for SSR hydration)
- Separate `@nexus-state/time-travel` package exists with `TimeTravelController` and `SimpleTimeTravel`
- `DevToolsPlugin` (in `plugins/devtools.ts`) has history for Redux DevTools time-travel

**Why it was never implemented:**

1. Over-engineered design (full time-travel manager vs simple snapshot/restore)
2. Low user demand (no issues/requests for time-travel)
3. Separate `@nexus-state/time-travel` package already exists
4. DevTools plugin provides time-travel via Redux DevTools Extension

## Requirements

Make an **explicit decision** and document it. Three options:

### Option A: Accept (Move to Future Phase)

**Decision:** Time-travel is a valuable feature, but out of scope for Phase 14.

**Rationale:**
- Core state management is stable
- Time-travel is a "nice to have", not essential
- Separate `@nexus-state/time-travel` package exists for users who need it
- DevTools plugin provides time-travel via Redux DevTools

**Action:**
- Create new planning phase (Phase 15 or later) for time-travel
- Simplify design: just `snapshot()` / `restore()`, no `TimeTravelManager`
- Document in `INDEX.md`: "Time-travel deferred to Phase 15"

### Option B: Reject (Will Not Implement)

**Decision:** Time-travel will not be implemented in core.

**Rationale:**
- Separate `@nexus-state/time-travel` package exists
- DevTools plugin provides time-travel via Redux DevTools
- Adds complexity to core (history management, memory overhead)
- Low user demand
- Violates "minimal core" principle

**Action:**
- Document in `INDEX.md`: "Time-travel rejected — use `@nexus-state/time-travel` or DevTools"
- Update `README.md` to point users to time-travel package
- Remove time-travel from future planning

### Option C: Defer (Postpone Decision)

**Decision:** Postpone decision until user demand is clearer.

**Rationale:**
- No urgent need for time-travel
- Separate package exists
- May gather user feedback in future releases

**Action:**
- Document in `INDEX.md`: "Time-travel deferred — decision pending user feedback"
- Add GitHub issue/discussion to gather feedback
- Revisit in 6 months

## Implementation (Option B Recommended)

### 1. Create Decision Document

```markdown
# Time-Travel Decision

**Date:** 2026-07-10  
**Decision:** REJECT — will not implement in core

## Rationale

1. **Separate package exists:** `@nexus-state/time-travel` provides time-travel functionality
2. **DevTools integration:** `devtools()` plugin provides time-travel via Redux DevTools Extension
3. **Low user demand:** No GitHub issues or discussions requesting time-travel
4. **Complexity:** Time-travel adds history management, memory overhead, and API surface
5. **Minimal core principle:** Core should be small and focused on state management

## Alternatives

Users who need time-travel can:

1. Use `@nexus-state/time-travel` package:
   ```typescript
   import { TimeTravelController } from '@nexus-state/time-travel';
   const controller = new TimeTravelController(store);
   controller.back();
   controller.forward();
   ```

2. Use `devtools()` plugin with Redux DevTools Extension:
   ```typescript
   import { devtools } from '@nexus-state/core/devtools';
   const store = createStore({ plugins: [devtools()] });
   // Use Redux DevTools UI for time-travel
   ```

3. Implement custom snapshot/restore:
   ```typescript
   const snapshot = store.getState();
   store.setState(snapshot);
   ```

## Future Considerations

If user demand increases, reconsider in a future phase with simplified design:
- `store.snapshot()` / `store.restore(snapshot)` only
- No `TimeTravelManager` class
- No `back()` / `forward()` / `historyLength` API
- Leave advanced features to `@nexus-state/time-travel` package
```
