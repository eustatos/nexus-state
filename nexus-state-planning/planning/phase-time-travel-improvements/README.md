# Phase: Time-Travel Improvements

## Цель

Улучшить UX и надёжность time-travel функциональности в `@nexus-state/time-travel` путём устранения неинтуитивного поведения `capture()` и предотвращения проблем с дублированием имён атомов.

## Контекст

### Текущие проблемы

1. **`capture()` требует явной инициализации атомов**
   - `capture()` возвращает `{}` для атомов, которые не были явно инициализированы через `store.get()` или `store.set()`
   - Разработчики ожидают, что `atom('initial', 'name')` создаёт атом со значением, доступным для snapshot
   - Требуется дополнительный бойлерплейт: `store.set(atom, 'initial')` перед `capture()`

2. **Дубликаты имён атомов**
   - `atomRegistry` позволяет регистрировать несколько атомов с одинаковым именем
   - `getByName()` возвращает первый найденный атом (недетерминированное поведение)
   - Может вызвать проблемы в DevTools и time-travel

### Архитектурное решение

После анализа было решено **сохранить текущую архитектуру** (atom как метаданные + store как состояние), так как она:
- Обеспечивает изоляцию per-store (критично для SSR)
- Позволяет независимые time-travel timeline'ы для разных store
- Соответствует заявленным целям проекта (framework-agnostic, multi-framework support)

## Решение

### Вариант 1: Авто-инициализация в `capture()` (рекомендуется)

`capture()` автоматически инициализирует все атомы из `atomRegistry` перед созданием snapshot.

**Плюсы:**
- Прозрачно для пользователя
- Не ломает существующий код
- `capture()` работает "как ожидается"

**Минусы:**
- Инициализирует все атомы (даже неиспользуемые)
- Может вызвать вычисления computed атомов

### Вариант 2: Warning при дублировании имён

Добавить предупреждение в `atomRegistry.register()` при обнаружении дубликата имени.

### Вариант 3: Документация

Явно описать поведение `capture()` и рекомендации по использованию уникальных имён атомов.

## Риски

- **Performance:** Авто-инициализация всех атомов может быть медленной для больших приложений
  - *Митигация:* Документировать, рекомендовать явную инициализацию для production
- **Breaking changes:** Computed атомы могут вычисляться неожиданно
  - *Митигация:* Тесты должны покрыть этот сценарий
