# TASK-09: Рефакторинг ComputedAtomHandler.ts + тесты

## Описание
Рефакторинг `time-travel/tracking/ComputedAtomHandler.ts` с разделением на меньшие классы и написанием тестов

## Метаданные
- **Приоритет:** Высокий (P1)
- **Сложность:** Очень высокая
- **Оценка:** 16 часов
- **Файл:** `packages/core/src/time-travel/tracking/ComputedAtomHandler.ts` (220 строк)
- **Текущее покрытие:** 14.5%
- **Целевое покрытие:** ≥ 90%

## Требования
- [ ] **strict: true** — никаких `any`, все типы явные
- [ ] **SPR** — разбить на 4-5 PR ≤ 200 строк каждый
- [ ] **TDD** — characterization tests перед рефакторингом
- [ ] **SOLID** — соблюдение принципов после рефакторинга
- [ ] **Покрытие:** ≥ 90% для всех новых файлов

## Проблемы текущего кода
1. Нарушение SRP — класс делает слишком много
2. Высокая цикломатическая сложность
3. Трудно тестировать из-за смешанных ответственностей
4. Скрытые зависимости между методами
5. **Сильные зависимости:** AtomTracker, store.get(), subscribe()

## Стратегия: Сначала рефакторинг, потом тесты

**Обоснование:** Текущая архитектура делает тестирование чрезмерно сложным:
- Требуются сложные моки для AtomTracker
- Приватный API (`this.tracker["store"]`)
- Событийная модель (`subscribe()`)
- `setTimeout` в логике

**Решение:** Разделить на независимые классы, затем тестировать каждый изолированно.
