# ART-006: Техническое ревью (Technical Review)

## 📋 Описание

Проверка технической точности статьи: работоспособность примеров кода, корректность терминологии, соответствие документации Nexus State.

## 🎯 Цель

Убедиться, что статья технически точна и все примеры кода работают без ошибок.

## 👥 Роли в ревью

| Роль | Обязанности | Критерии |
|------|-------------|----------|
| **Технический ревьюер** | Проверка кода, терминологии | Глубокое знание Nexus State |
| **Редактор** | Стиль, грамматика, поток | Опыт технических публикаций |
| **Бета-читатель** | Восприятие новичком | Представитель ЦА |

## 📝 Чек-лист ревью

### Раздел 1: Проверка примеров кода

**Для каждого примера:**

- [ ] **Синтаксис**: Нет ошибок TypeScript/JavaScript
- [ ] **Импорт**: Все импорты корректны и существуют
- [ ] **Версии**: API соответствует текущей версии Nexus State
- [ ] **Контекст**: Пример работает без дополнительных зависимостей
- [ ] **Ожидание**: Результат соответствует описанному в статье
- [ ] **Копирование**: Можно скопировать и запустить без правок

**Процесс проверки:**
```bash
# 1. Создать тестовый проект
pnpm create vite@latest article-test --template react-ts
cd article-test

# 2. Установить зависимости
pnpm add @nexus-state/core @nexus-state/react

# 3. Для каждого примера:
#    - Скопировать в файл
#    - Запустить
#    - Проверить результат
#    - Отметить в чек-листе
```

**Ключевые термины:**

|--------|-------------------------|--------|
| Atom | Существительное, единица состояния | ⬜ |

- [ ] Первое упоминание термина объяснено

### Раздел 5: Проверка потока и логики

**Вопросы для проверки:**

1. **Введение**
   - [ ] Захватывает внимание
   - [ ] Чётко обозначает проблему
   - [ ] Обещает решение
   - [ ] Даёт обзор статьи

2. **Основная часть**
   - [ ] Логическая последовательность
   - [ ] Каждый раздел вытекает из предыдущего
   - [ ] Нет скачков в сложности
   - [ ] Примеры иллюстрируют теорию

3. **Заключение**
   - [ ] Подводит итоги
   - [ ] Повторяет ключевые моменты
   - [ ] Даёт призыв к действию
   - [ ] Содержит следующие шаги

4. **Общее**
   - [ ] Нет повторений
   - [ ] Нет противоречий
   - [ ] Стиль консистентен
   - [ ] Тон соответствует аудитории

### Раздел 6: Проверка производительности (если применимо)

**Метрики для проверки:**

| Метрика | Заявлено | Реально | Статус |
|---------|----------|---------|--------|
| Время захвата снимка | < 50ms | ⬜ | ⬜ |
| Время восстановления | < 100ms | ⬜ | ⬜ |
| Размер снимка (delta) | < 1KB | ⬜ | ⬜ |
| Потребление памяти | < 50MB | ⬜ | ⬜ |

**Процесс проверки:**
```typescript
// В консоли демо-приложения
const start = performance.now()
timeTravel.capture('test')
const end = performance.now()
console.log('Capture time:', end - start, 'ms')
```

## 🔧 Процесс ревью

### Этап 1: Саморевью (1 час)

**Автор проверяет:**
- [ ] Все примеры кода
- [ ] Все ссылки
- [ ] Все визуалы
- [ ] Орфографию и грамматику

### Этап 2: Техническое ревью (2-3 часа)

**Технический ревьюер:**
- [ ] Запускает все примеры
- [ ] Проверяет терминологию
- [ ] Сверяет с документацией
- [ ] Заполняет форму обратной связи

### Этап 3: Бета-чтение (1-2 часа)

**Бета-читатель:**
- [ ] Читает статью целиком
- [ ] Отмечает непонятные места
- [ ] Оценивает сложность
- [ ] Заполняет форму обратной связи

### Этап 4: Внесение правок (2-3 часа)

**Автор:**
- [ ] Исправляет критические ошибки
- [ ] Учитывает замечания
- [ ] Обновляет примеры
- [ ] Перепроверяет ссылки
